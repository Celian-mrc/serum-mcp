# Real-Serum test log

Running record of what this project has actually verified by loading a
generated/edited `.SerumPreset` in real Serum 2 (FL Studio 21 host), versus
what only passes the automated `scripts/check_preset.py` scan and unit
tests. Both matter, but they catch different failure classes — see
`CONTRIBUTING.md`'s "Evidence standard" and the `test-in-serum` skill for
why the distinction is load-bearing (the project's first fully-tested
preset still crashed FL Studio from a bug no round-trip check caught).

Update this file whenever a feature crosses from "written + unit-tested"
to "loaded in real Serum and confirmed" — or when a live load surfaces a
bug, note that too, since a fixed-after-live-testing feature is stronger
evidence than one that merely round-trips.

## Closed investigations (not reproducible)

- **`TEST - Role Audit SY` crashed FL Studio once** on its first load. `check_preset.py` found no CBOR wire-type issue. Bisected: `FXPhaser` alone loaded fine; the full preset minus `FXPhaser` also loaded fine; reloading the ORIGINAL crashing file a second time did NOT crash. ## Not yet tested live

Written, unit-tested, and passes `check_preset.py`, but not yet confirmed
by an actual load in Serum:

- `list_sample_files` / `analyze_sample_file` tools (sample browsing +
  acoustic descriptors) — these don't write preset files themselves, so
  "testing" them means confirming their output correctly informs a
  `sample_playback_source` choice that then loads/sounds right. Note:
  `analyze_sample_file`'s `peak_dbfs`/`rms_dbfs` fields were used to choose
  volumes in the 2026-07-29 layering test above, but only via a direct
  `uv run --no-sync` call bypassing a stale-at-the-time MCP server process
  — not yet exercised through the live `analyze_sample_file` MCP tool
  itself since the restart.
- Embedded WAV metadata reading (`inst`/`smpl`/`acid` chunks) in
  `analyze_sample_file`.
- `OscillatorSpec.semitone` pitch alignment specifically (as opposed to
  whole-octave `octave` correction, confirmed above).
- Configurable `SAMPLE_BANK_PATH` (default sample bank location).
- Mod matrix sources `aftertouch`, `poly_aftertouch`, `env1`, `env2`,
  `env3` — source IDs are `confirmed` (see the row above), but no
  `serum-mcp`-*generated* preset using these has been audibly tested live
  yet (only unit-tested round-tripping).
- The remaining 6 of 8 `role_starting_points` roles (lead, pad, chords,
  synth, arp, sequence) — bass and pluck are confirmed live (see above),
  the rest follow the same doc/table but haven't been generated and
  listened to yet.
- Multi-rack FX (`FxUnitSpec.rack`) — verified structurally correct against
  Galaxy's real raw data (13 FX units across 2 racks extracted correctly,
  round-trip tested, unit tests pass) but not yet loaded in real Serum with
  a generated multi-rack preset to confirm it actually sounds/behaves right
  (e.g. that rack 1 truly runs in parallel with rack 0, not silently
  ignored or serialized). `TEST - Galaxy Recreation` v3 is the first real
  test of this once loaded.
